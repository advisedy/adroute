## 2. 产品目的与本轮必须改变的事情

AdRoute 是通用的本地模型代理，不是某个客户端的专用前端。日常操作必须围绕下面这条主线：

> 添加模型 → 提供上游 Base URL 和上游 API Key → 选择或填写真实模型 ID → 设置模型名称、选择自建组 → 保存 → 客户端通过统一的本地地址和代理密钥调用。

本轮不是把“供应商”三个字改成“组”，也不是仅调整 CSS。当前实现的“Provider → Key → 模型”所有权结构与管理流程要调整为真正的“用户自建组 + 各自拥有连接配置的模型”。

用户不需要先建立供应商或 Key，才能添加模型。组不继承 URL、不继承凭据、不代表某个厂商品牌，也不提供轮换或故障转移。

## 4. 目标数据模型和唯一性

### 模型组

- 用户自行创建。
- 每个模型必须属于且只属于一个组。
- 组只包含稳定内部身份与组名等必要信息，不保存公共 URL 或公共 API Key。
- 组名全局唯一。
- 合法组名：小写 ASCII 英文字母、数字以及单个连字符；不能以连字符开头/结尾，不能连续连字符。
- 校验规则可直接使用：`^[a-z0-9]+(?:-[a-z0-9]+)*$`。
- 不接受中文、空格、下划线或斜杠作为组名；直接返回清楚错误，由用户手动修改。不要自动改成拼音、去空格或转小写后保存。
- 只有空组可以删除。有模型的组要明确报错，要求用户先移动或删除模型；不得级联删除或自动搬到“未分组”。

### 模型条目

每个条目至少表达这些含义：

- 稳定的内部 ID；可以沿用 UUID，不对用户暴露为公开模型 ID。
- 所属组的内部 ID。
- 模型名称。
- 上游真实模型 ID。
- 此模型自己的上游 Base URL。
- 此模型自己的上游 API Key。
- 对外开放状态。
- 当前逐模型兼容修复绑定所需信息。

可以采用平铺的 `groups` 与 `models` 集合，也可以使用同样简单的组内模型结构；不要同时维护两份权威模型数据。选定一种，持久化和接口保持清晰，默认选择、诊断与修复等内部引用使用稳定条目标识，不依赖可修改名称。配置版本如需变化，只支持一个新的当前格式，不写兼容转换器。

### 模型名称与真实模型 ID 必须分开

- 真实模型 ID 是发给上游的精确值，可以包含上游本来允许的 `/`、大小写等。不要对它应用公开名称的字符过滤，也不要改写成用户名称。
- 模型名称是用户主动指定、对外使用的名字。
- 合法模型名称：一个或多个 ASCII 英文字母、数字、`.`、`_`、`-`，对应 `^[A-Za-z0-9._-]+$`。
- 不接受中文、任何空白、`/` 或其他字符；前端提示，后端同样拒绝。不要静默裁剪、替换或翻译。
- 同组内模型名称唯一，按原样精确、区分大小写比较；不同组可以同名。
- 已关闭的模型仍占用组内名称，不能在关闭期间重复创建同名条目。
- 重名返回明确冲突错误，要求用户手动修改。禁止自动追加序号。
- 名称字符合法性不等于允许把它用作文件路径。持久化路径不要由用户名称拼接，仍遵守既有安全文件操作约束。
- 长度和条目数量等安全上限可以沿用现有合理限制，并在接口文档中写明；不要通过删除上限来让测试通过。
- 同一组允许真实模型 ID 相同但模型名称不同的两个条目；它们可以来自不同地址、不同 Key，也可以是用户明确创建的两个配置。
- 不以 URL、API Key 或真实 ID 为由强制合并模型。修改一个模型的 Key 不能影响任何其他模型。
- 唯一性在后端持久化事务内校验。两个并发请求创建同组同名模型，只能有一个成功，不能只靠前端检查。

### 新建时名称的默认填写

- 用户填写/选择真实模型 ID 时，在用户尚未手动修改名称的前提下，把它填入模型名称。
- 若默认填入的名称非法，例如真实 ID 是 `vendor/model`，展示名称错误并阻止保存，请用户手动取合法名称；不要偷偷变成 `vendor-model`。
- 用户手动改过模型名称后，后续输入真实 ID、发现结果返回或刷新不能覆盖它。
- 编辑已经保存的模型时，修改真实 ID 不自动修改现有名称。

## 5. 对外模型 ID、路由和编辑语义

唯一公开规则：

```text
adroute/<组名>/<模型名称>
```

例子：

```text
组名：               work
模型名称：           coding
上游真实模型 ID：    vendor/model
上游 Base URL：      https://example.invalid/v1
上游 API Key：       此模型保存的凭据

客户端获取并选择：   adroute/work/coding
目录展示名称：       work / coding
实际发给上游的 model：vendor/model
```

必须做到：

1. `/v1/models` 的 `id` 本身就是上述公开 ID，不能返回上游真实 ID 或 UUID。不能只改 `display_name`，因为有些客户端只显示 `id`。
2. name/display_name 等展示字段使用组名和模型名称。管理界面仍可显示真实 ID 供用户排查；公共目录不额外泄露上游 Key 等信息。
3. Codex 模型目录、OpenCode 显式同步、代理解析与公开模型列表使用同一套规则，不能各自拼接出不同 ID。
4. 不接受用户直接把任意原始上游 ID 当成 AdRoute 固定路由来调用。
5. 修改 Base URL、API Key 或真实模型 ID，而组名/模型名称没变，对外 ID 保持不变，内部条目身份也不必重建。
6. 这是用户主动改接上游，正常保存即可。不增加“替换模型向导”、额外风险确认、强制新名称或新路由。不要恢复早期“改真实 ID 就必须创建新条目”的规则。
7. 改组名、模型名称或把模型移动到别组，会改变公开 ID。保存前提示旧客户端选择将失效；取消不修改。移动需检查目标组重名，不自动改名。
8. 只改地址、Key 或真实 ID 不要求用户重新获取目录；后续请求使用已保存的新上游配置。
9. 改名、换组、增删或开放状态变化，应更新目录并提示客户端重新获取，必要时重新选择。不能承诺所有客户端会自动刷新。
10. 旧 ID 不做兼容映射、不自动跳转、不回退到默认或其他模型。
11. 名称按当前配置寻址。用户主动重建同组同名条目，或者主动改接它的上游，属于用户配置行为；不增加永久保留历史名称、墓碑或版本路由系统。

现有兼容修复是显式的逐条目配置，不从组继承，不因普通编辑自动套用其他条目的绑定。不要仅因为修改真实 ID 就删除条目再重建。任何必要的修复绑定失效策略应与现有协议安全约束一致，并在报告里明确说明，不暗中增加新产品流程。

## 6. 开放状态和默认模型

- 新模型默认开放，添加表单可在保存前关闭。
- 对外开放与设为默认是两个独立概念。
- 开放的模型进入目录并能固定路由调用，不需要先设为默认。
- 关闭模型保留其配置，管理页仍显示并允许编辑、显式测速和删除。
- 所有面向客户端的目录只列开放模型，包括实际发布的 Codex 文件与 OpenCode 显式同步结果。
- 缓存的关闭模型 ID 也要拒绝，返回既有语义的 403 `MODEL_ROUTE_DISABLED`；未知或已删除 ID 仍是明确的 not-found，不尝试其他目标。
- 网页默认模型只是可选的辅助设置，不再是首页大卡片。
- 只能从开放模型中选择默认，设为默认不改变其他模型的开放状态，也不能隐式打开关闭条目。
- 关闭当前默认模型先确认，确认后关闭状态与清空默认在一次后端变更中完成；取消不得发修改请求。
- 删除当前默认模型也清空默认。不自动替换；重新开放不恢复旧默认。
- `adroute/default` 继续只在有效开放默认存在时进入目录。省略 model 的默认行为及对 null/数字/空字符串的拒绝保持现有明确合同。
- 普通编辑不能因旧草稿携带陈旧的开放状态而重新打开服务器已经关闭的条目。未修改的开放状态应省略或使用等效并发保护。
- 请求到达时固定路由快照。已接收请求可以按旧快照完成，新请求立即使用新状态；不取消所有在途请求来实现开关。
- 开放状态、默认选择、目录生成与持久化之间不得出现半完成的领域状态；保留现有文件发布失败的报告/重试保护，不伪称多文件写入天然具有跨文件原子性。

## 7. 页面与操作要求

### 首页

- 页面名以“模型管理”等直观用语为主，不以 Codex 为首页主语。
- 顶部紧凑展示本地 Base URL、本地代理 API Key，分别有复制操作；代理密钥默认遮蔽，可显式显示。管理令牌、代理密钥、上游 Key 不得混淆。
- 说明本地入口支持本轮现有 Responses 能力，不写“兼容所有客户端”。
- 有“全部模型”和各用户组的筛选，提供新建组、组改名、空组删除入口。
- 主要按钮为“添加模型”。
- 模型行/卡片显示：组名/模型名称、上游真实模型 ID、地址概要、开放状态。列表中不展示明文 Key。
- 每条模型都有并排的小按钮：**编辑 / 测速 / 删除**。三个都直接可见，删除不能藏到更多菜单里。
- 开放开关直接显示。移动端允许按钮组换行，不能挤出屏幕，也不能因窄屏隐藏删除或测速。
- 测速结果放在对应模型下方，测试状态与取消操作就近展示，不弹出复杂测速报告。
- 次级保留请求记录、客户端接入与恢复、兼容修复、默认模型设置。首页不堆满原来的大型统计、教程和默认路由卡片。

### 单个添加/编辑表单

- 一次直接编辑模型自身的 URL、Key、真实 ID、模型名称和所属组。
- 不出现“先选供应商，再管理 Key，再保存一整份 Key 模型清单”的绕路。
- “获取模型”使用表单当下填写的 URL/Key，包括尚未保存的新值；不能误用旧凭据。
- 获取结果只用于让用户选择一个具体模型，不自动保存全部结果、不自动推理。
- 获取失败不阻止手工填写真实 ID；清楚说明列表可获取不代表推理一定可用。
- 可以在表单内新建组，不强制跳到另一页；从某个组添加时预选当前组。没有隐藏“未分组”桶。
- Key 默认遮蔽，允许明确查看/替换；失败保留草稿。未明确修改的 Key 不得被空输入或掩码覆盖。
- 一个模型保存成功或失败是清楚的一次行为；不要先保存一半，再让前端用多个补救请求维持默认/开放一致性。
- 保存不自动测速、不自动登录、不写客户端文件。
- 名称非法、重名、组不存在等错误要在字段附近解释，后端直接调用同样拒绝；不使用原始技术堆栈错误吓用户。

### 删除与异步状态

- 删除模型前有明确确认，标出所删模型；取消不请求删除。
- 修改组/名称和关闭默认的确认规则按前文执行，不给普通连接配置编辑增加额外确认。
- 同一操作进行中防止重复提交；失败恢复保存前的真实状态，不能假装成功。
- 关闭弹窗、切组、刷新、重新打开、退出登录时，晚到的异步响应不能覆盖新草稿、显示其他条目结果或恢复私有数据。
- 不能只禁用旧 DOM 中的按钮：重渲染后还应根据当前 pending 操作保持同一条目的单飞。
- 不要为了这些要求引入通用前端状态框架，使用聚焦的小控制器/函数维护即可。

## 8. 快速测速：完整行为与计算规则

用户要求：主要检查能不能通，尽快返回，顺带报告一个粗略的每秒输出 token 数，不建设专业跑分工具。

### 8.1 调用

- 点击行内“测速”即发起一次短文本请求，不弹出额外确认；模型区域保留可能产生少量费用的说明。无需复杂多页设置。
- 针对该已保存模型的一份配置快照，调用它真实 URL/Key/真实模型 ID 的 Responses 接口。
- 这是实际文本生成检查，不是 GET `/models`、TCP ping、只看响应头或 HTTP 200。
- 固定提示词要求连续输出 1～120 的整数，以空格分隔，不加解释或代码块；限制输出，避免工具调用。不要求用户填参数，也不把数字个数当作 token 数。
- 单次输出上限 1024 tokens（包含推理）、总超时 18 秒。旧 192 tokens 上限可能在推理阶段耗尽，无法检验正文返回；为推理留出额度，但不额外建设产品设置页。慢模型可能超时，UI 应说明“本次测速超时”，不因此永久关闭模型。
- 每次最多一个请求，不自动重试，不批量跑，不在打开页面/保存/刷新时后台测试。
- 已关闭模型可以由已登录管理用户显式测速，但不能因此开放它，也不能让普通代理调用绕过关闭。
- 测速不得修改默认、修复绑定、客户端配置或其他模型。

### 8.2 成功与数据来源

- 收到结构有效的 Responses 响应及非空文本，才说明文本调用确实返回。
- 支持当前实际兼容的 SSE 和 JSON 响应。SSE 的 UTF-8、行与事件可能被任意网络分块，不能假定一次 Read 就是一个事件。
- 读取最终 usage 的 `output_tokens`；不要重复累计 delta、done、最终快照里的同一份文本或用量。
- HTTP 200、`[DONE]`、空 output、只有 reasoning/工具调用而没有文本，不能单独构成“文本成功”。明确解析 failure/incomplete 事件，不能只匹配一个字符串 completed。
- 达到输出上限的 incomplete 响应若已返回文本，应按真实原因展示，例如“已返回文本，达到本次测试输出上限”；不要把它伪装成完整成功，也不要错误解释成鉴权或网络不通。
- 达到输出上限但没有正文时，也必须展示额度耗尽的真实原因与用量；可信明细显示全部输出均为推理时，明确说明“本次输出额度全部用于推理，尚未返回正文”，不据此判定模型不可用。

### 8.3 参考速率

```text
正文 tokens = output_tokens - output_tokens_details.reasoning_tokens
缺少可信用量或推理明细时，参考正文 tokens = cl100k_base(实际可见正文)
输出阶段参考速率 = 正文 tokens / (最后一个正文分片时间 - 第一个正文分片时间)
```

- 所有耗时用后端单调计时，不取浏览器动画耗时；总耗时仍从开始请求到有效结束。
- 速率不含首字等待、推理 tokens、最后正文分片之后的结束事件等待。列表只显示“XX.X tokens/s”和小信息标识，详情注明“不含首字等待与推理 tokens，流式采样参考”。不设置 200 或 300 tokens/s 之类的速度上限。
- 单独显示首字延迟：从后端发起请求到收到第一个非空白 `response.output_text.delta`，忽略响应头、生命周期事件及空白分片；不被后续分片重置。JSON 或只有最终快照的响应不推算首字延迟；无 usage 时仍可显示实测首字延迟。
- `output_tokens` 可能含推理 tokens。对可信总用量，校验并展示 `output_tokens_details.reasoning_tokens`（允许 0，且不得超过总输出用量）；缺失或无效不默认为 0。对无其他非文本输出且不超过 4096 字节的短正文，使用离线内置的单一 cl100k_base 分词器估算可见正文用量，显示“约 XX.X tokens/s”，详情明确该估算不是上游计费 token 数、可能与该模型分词不同。不把推理内容计入估算，也不得把总 output_tokens 除以首字后的时间冒充纯文本生成速度。
- 至少两个非空白正文分片、32 个可信正文 tokens、50 ms 的输出跨度才给出速率；JSON、单分片及过短样本明确说明速度不可统计。首分片可能包含多个 tokens，因此这一速率仍是采样参考，不声称是精准逐 token 解码速度。
- API 的旧 `tokensPerSecond` 保留端到端口径供兼容使用；页面使用 `textTokensPerSecond`，不以旧值兜底显示速度。输出时长为 `textDurationMs`，正文用量为 `textTokens`，`textTokensSource` 为 `usage` 或 `cl100k_base-estimate`，无法计算的原因为 `speedUnavailableReason`。估算不设置 `usageReported` 或虚构 `reasoningTokens`。
- 只有可信、合理的输出 token 数和有效正耗时才计算；拒绝负数、非数字等无效 usage，不显示 NaN、Infinity 或负速度。
- 上游不返回 usage 时，可显示明确标注的本地分词估算速度；若流式计时或样本仍不满足条件，则显示不可统计并解释原因。
- **禁止把字符数、字节数、单词数或 SSE 事件数冒充 token 数。** 本地分词仅采用一种内置参考标准并明确标为估算，不建设多模型 tokenizer 注册表，不在运行时下载词表，也不要补发一次收费请求。
- 快速短样本的结果不精确是正常的；固定的连续数数样本避免一句话的过短输出，保持 1024 output tokens 上限、18 秒超时和单请求限制。不添加排行榜、历史趋势、自动选择最快模型或持久统计数据库。

### 8.4 取消、失败和界面

- 对应模型显示“测速中”，可取消，同模型不能重复发起。运行时暂时禁用该模型的编辑/删除，避免结果挂到变更后的目标上。
- 前端取消、退出或后端超时必须实际取消上游请求，关闭响应体；不能只停止浏览器等待而让后台继续生成。
- 新测速必须从 HTTP 请求的 context 派生总 deadline。现有 `Upstreams.Test` 使用 background context 的实现需要检查并调整，不能原样保留导致取消失效。
- 单次调用使用同一个总截止时间，不能每收到一个事件就重新延长超时。
- 区分：成功、缺少用量、无文本、上游错误、超时、用户取消。错误信息脱敏，不显示上游 Key 或完整敏感响应。
- 最近结果显示在对应模型下方；成功时只显示速度和一个小信息标识，失败或不可统计时保留简短状态。悬停或键盘聚焦标识、手机点击标识显示“速度 · 首字 · 总耗时 · 输出 tokens · 返回正文”，Escape/点击外部关闭，浮层不越出屏幕。只需当前登录页面中的最近结果；修改上游配置/真实 ID 后清除陈旧结果。
- 详情中的正文来自最终快照（无正文时退回实际文本 delta），不重复拼接最终快照与 delta，也不展示思考原文。后端先脱敏凭据、再按 Unicode 字符截断至 4096 字符，另报预览截断标志；仅当前页面内存持有，不写持久配置、日志或浏览器存储，退出后清除。前端用 textContent 显示，不执行模型返回的 HTML。
- 页面重渲染、关闭再打开界面不能导致同模型第二个请求；晚到结果、旧账号会话、已删除条目的结果不得污染当前界面。
- 完成文本测速不等于完成工具往返验证。原高级工具结构测试与官方 Codex 合成工具往返测试要保留。

- 创建、改名、删除组。
- 创建、编辑、删除、移动模型。
- 修改单个模型开放状态。
- 可选默认选择。
- 使用未保存 URL/Key 发现模型。
- 对已保存模型进行快速测速，以及保留高级工具结构测试。
- 按模型选择兼容绑定与诊断目标。
- 公共模型目录及固定路由解析。

不要同时保留一套旧 provider/key API 和一套新 API 作为过渡。无须迁移旧调用方；仓库内前端、CLI、测试和文档一起更新。

## 10. 实施方式：分段测试驱动，不一次性瞎改

1. 检查工作区、依赖和实际测试命令，先记录基线结果。不把旧项目源码当作你自己的可丢弃临时文件。
2. 如需对比，可把必要源码/测试基线保存在 `/tmp/opencode` 的专用目录，不读取真实凭据，不用 Git destructive 命令恢复文件。
3. 先写新数据/组模型约束与路由测试，实际跑出预期失败，再实现最小后端。
4. 更新公共目录、默认/开放、兼容寻址与客户端配置接入，逐项跑测试。
5. 用合成上游先测试测速解析、指标和取消，再实现它；不要用真实 Key 找问题。
6. 编写真实 Go 二进制的浏览器行为测试，再实现新管理界面和异步状态。
7. 删除确认不再需要的旧产品分支，改文档，完整回归。
8. 每阶段可暂时存在尚未迁移的旧测试失败，但最终必须解释清楚并完成所有保留功能的回归。不得靠删测试、skip、放宽断言来取得绿灯。

已明确删除的订阅功能测试可以删除，旧 provider/key 用例可以改写成等效组/模型用例；其他安全、配置恢复、流式协议、工具修复、默认、开放与真实工具往返覆盖不能因为改了数据模型就消失。

## 11. 必须覆盖的验收场景

### A. 组、名称、凭据和编辑

1. 一个组内保存来自不同 URL/Key 的模型。
2. 同一 URL/Key 的模型进入不同组，彼此独立。
3. 同组相同真实 ID、不同模型名称可以保存。
4. 同组同模型名称不能保存；不同组同名可以。
5. 关闭模型仍占名；并发创建/移动同名只允许符合约束的一次成功。
6. 中文/空白/斜杠等非法模型名称前后端均拒绝，原输入不被自动转换，无自动后缀。
7. 新建模型名称自动随真实 ID 填写；用户改过名称后不被晚到发现结果覆盖。
8. 真实 ID 含 `/` 时原样用于上游，但名称非法时需用户手改。
9. 只改真实 ID、URL 或 Key，对外 ID 与内部条目身份保持，之后请求确实改用新的上游配置，其他模型不变。
10. 改名/移动/组改名使旧公开 ID 失效，新 ID 可用；取消确认零变更。
11. 非空组删除失败；空组可删除；删除模型确认取消不删除。
12. 保存/校验失败不破坏之前持久化状态；重启隔离二进制后配置与默认/开放状态保持。

### B. 目录、路由、开放和默认

13. 真正 GET `/v1/models` 返回 `adroute/组/模型名称`，真实合成上游实际收到真实模型 ID 与正确 Key。
14. 相同真实 ID 的不同条目不会串凭据，不从组继承连接，不发生失败回退。
15. 关闭后从公共模型列表、实际 Codex 目录文件和显式 OpenCode 同步文件中消失，管理页仍保留。
16. 缓存旧 ID 请求关闭模型被拒绝且没有上游请求；未知/删除/旧 raw model ID 不自动转向其他模型。
17. A 设为默认后改成 B，A 仍开放可调用；不能把设默认当作独占开关。
18. 关闭当前默认时，取消零变更，确认一次领域事务完成关闭+清默认；重新开放不恢复默认。
19. 新旧快照：接收前关闭的新请求拒绝，关闭前已接收请求仍按原快照完成。
20. 陈旧编辑草稿不能悄悄重新开放服务器关闭的条目。
21. 无默认时目录不虚列 `adroute/default`；显式/省略 model 的既有错误语义正确。
22. 单纯修改模型或开放状态不得自动写 OpenCode 外部配置；显式同步才写，保留注释和用户编辑等安全要求。

### C. 快速测速

23. 合成 SSE 正常文本+usage，返回合理的正 token/s 与耗时；测试数值公式，允许计时容差。
24. 合成 JSON 正常文本+usage 的处理正确。
25. 文本可用但无 usage，不编造速度，不把空值显示为 0 token/s。
26. 200 空结果、只有 `[DONE]`、无文本、failed、错误结构、HTTP 错误不能都变成“可用”。
27. arbitrary SSE chunk boundaries、末尾事件、有效完成状态以及输出上限的 incomplete 场景被正确解释。
28. 超时和用户取消能让合成上游观察到断开/取消，不只是前端计时器结束。
29. 取消用量确认零推理请求；确认恰好一个请求，不重试。
30. 同模型重复点击、刷新重渲染、关闭再打开界面保持单飞；测试中编辑/删除不可用。
31. 关闭模型的管理测速不会开放它，不会改变默认或其他模型。
32. 修改上游目标后旧测速结果清除；退出登录后晚到测速结果不恢复私有信息。
33. 无效/负数 usage、极短计时不产生 NaN/Infinity/负速度；结果不包含真实密钥或敏感全文。

### D. 实际界面与保留功能

34. 浏览器使用实际编译的 Go 二进制，不只 mock fetch 后端或跑静态 HTML。
35. 首页可直接添加、发现/手填、保存、编辑、移动、开放/关闭、测速、删除模型。
36. 每行“编辑 / 测速 / 删除”并排，桌面和手机都可访问。
37. 本地地址与密钥来自后端真实接入配置，不是硬编码示例；遮蔽/显示/复制行为正确且不混上游 Key。
38. 认证失败、API 失败、保存失败、测速失败、重名错误都有可理解反馈；草稿与真实状态不互相覆盖。
39. 保留退出登录隐私清理、旧响应保护、能力不匹配提示和无未捕获前端异常的覆盖。
40. Codex 配置接入/恢复、OpenCode JSONC 安全同步、CLI 生命周期与安装器相关保留测试通过。
41. v1/v2/v3 修复与诊断隐私保护仍通过，具体模型选择不再依赖 provider/key。
42. 官方 Codex 合成工具往返验收保留并运行，不能因为删除订阅来源就一起删掉。
