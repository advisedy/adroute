# Responses 兼容适配包（实验）

适配绑定属于单个已保存的模型条目，没有组默认、继承或“共享凭据”概念。配置只接受当前结构（version 5），不提供旧配置转换；重新配置时需为模型条目重新选择修复包。

## 用户怎么用

1. 更新 AdRoute 二进制后，在无重要请求时自行重启服务，打开管理页的“兼容适配”。
2. 点击“复制排查 Prompt”，交给有本地文件权限的 AI，并补充报错。先选择具体模型条目，Prompt 带入条目标识、对外模型 ID 和真实模型 ID（不含凭据）；未选择时先确认，不能猜测。
3. AI 按 Prompt 分析、在本机验证，将候选包直接写到页面显示的 `adapters/` 目录，无需下载再上传。未知问题可能需要更多诊断或扩展引擎，不保证每次都能产出包。
4. 点击“刷新修复包”。adroute 自己检查格式和包内样例，通过后才进入可选列表；刷新不调用模型、不执行命令、不自动绑定。
5. 在“明确绑定模型”选择**已有模型条目**，选择合格版本并保存绑定；不改变网页默认或客户端选择。组内其他真实 ID 相同的模型也不受影响。
6. 关闭修复写入该条目的 `none`；选旧版本回滚。新条目默认不修复，没有服务默认和继承机制。

“修复包管理”是折叠的小模块：显示版本、来源文件、校验结果和绑定情况。未绑定的包可确认后移除，同时清理登记和对应候选文件；已绑定的包需先解除绑定。坏文件可单独清理，目录或特殊文件不会递归删除。

v2 示例为 `examples/pixel-swe-v2.adroute-adapter.json`（`pixel-swe-tools@1.1.0`）；旧版 `examples/pixel-swe.adroute-adapter.json` 及 v1 行为保留。新包只会在包含相应引擎的 AdRoute 二进制中可用；更新二进制不会自动迁移旧配置或替换已有包/绑定。它不是所有模型或真实客户端已完全兼容的保证。正常路由仍逐字节透传，只有明确绑定的流式 Responses 请求经过适配。

## 遇到新问题，交给 AI 什么

完整任务模板见 [给 AI 的修复包制作提示词](repair-agent-prompt.md)，包含诊断、能力判断、验证、落盘和禁止自动启用的约束。页面按钮会填入真实路径；复制失败时展开全文供手动复制。

选择具体模型条目，再点“采集下一次匹配请求”。按条目 ID 与真实模型 ID 同时匹配，其他同真实 ID 的条目不会触发。它不自动发送推理请求，只取样之后的一次正常请求，最长两分钟、最多 256KB / 256 个事件。一次只允许一个等待或采集任务。

默认只采摘要：HTTP 状态、阶段耗时、事件类型、ID 关联、参数字段类型与长度，不保存参数值或文本。摘要不适合无损回放。

确有需要时，勾选“额外保留事件内容”并单独确认风险。处理结束后，脱敏事件暂存在本机数据目录 `diagnostics/capture-<取样ID>.json`（目录 700，文件 600）。每次取样使用新路径，绝不将旧 Prompt 的路径复用于新内容。重新采集或“停止并清除诊断”会清理本模块的旧取样文件及旧版 last-capture 文件，不递归删除其他文件。重启不自动载入旧内容，可主动清除遗留取样。页面退出只清空浏览器预览，不等于删除已授权的本机文件。

先预览，再勾选允许导出或让本地 AI 读取，才分享。再次复制 Prompt 时，仅在目标、取样 ID、完整性和已保存文件指纹都一致时附路径、取样 ID 与 SHA256；默认复制不附路径。AI 应先在本机核对指纹，不匹配或文件不存在时停止，而不是寻找另一份诊断。取消共享确认或更换预览会使待复制内容失效；已交给外部的文字无法收回，清除诊断可使旧路径失效。认证字段和已知密钥会脱敏，其他代码、路径、未知业务密钥仍可能敏感。脱敏会影响复现，截断样例不能当完整调用。取样不是逐字节网络抓包，解析失败标记 `parseError`。

可以把下面要求连同审查后的诊断和示例包交给 AI：

> 请分析这个 adroute Responses 诊断。先区分网络/请求问题和工具流问题。根据实际支持的 responses-tools-v1/v2 选择能力，按示例生成版本化的 .adroute-adapter.json：保留真实 call_id，不生成脚本，不包含凭据，附合成事件与准确 expectedCalls。最终快照重新生成 item ID 的情况需要 v2。不要把工具参数、命令内容、文本或模型 ID 写入处理代码；能力不足或参数无法可靠配对时明确停止。

取得包后，可先跑包内样例；也可预览一份未截断、含内容的诊断，在上方选择具体包版本后点“用选中适配包回放诊断”，不必先保存绑定。回放不会执行事件里的任何工具。

## 文件格式与能力

### 固定目录与已有包

- 目录为当前实例数据目录的 `adapters/`（由 `ADROUTE_HOME` 或现有 XDG/HOME 规则确定），不是固定的 Windows 下载文件夹。另有私有 `repair-work/` 用于 AI 的临时候选；实际绝对路径由页面和 Prompt 提供。
- 只在用户点击刷新时检查直属 `<id>@<version>.adroute-adapter.json` 文件，不递归，不监视后台文件变化；临时文件不登记。每次最多检查 128 个候选，超过时提示先清理。
- 拒绝读取符号链接、硬链接、目录、特殊文件、超限或未写完的 JSON。坏文件不会被启用，也不阻断其他包的管理。Linux/WSL 上固定打开的目录句柄，防止文件操作被目录替换重定向。
- 第一次刷新用符合大小上限的紧凑 JSON，将旧版已验证包写入临时文件并同步后，再排他发布到目录；中途失败不留半写的正式文件，遇到同名文件绝不覆盖。旧登记与绑定继续保留。
- 已验证包仍有不可变的登记快照。AI 修改同版本文件会报冲突，必须新版本；外部删文件会显示缺失，不会自动替换正在使用的版本。异常源文件不供新适配选择，已有请求/绑定继续使用验证快照。
- 管理器移除未绑定版本时清理文件和登记，避免下次刷新复活；删除失败明确报告，不假报成功。对坏符号链接只移除链接条目，不触及目标。不递归删除目录。
- 此功能不是 AI 的文件系统权限沙箱；若 AI 有整台机器写权限，仍需另行限制，不应放宽数据目录权限。

受限 JSON，无可执行脚本、任意表达式、请求头、URL、网络依赖或凭据字段；未知的顶层/选项字段会拒绝。包最多 256KB；最多安装 32 个版本且总量不超过 4MB。

必填字段：

- `schemaVersion`: `1`。
- `id`: 小写字母开头，之后只允许小写字母、数字、短横线，最多 64 字符。
- `version`: 三段数字版本，例如 `1.0.0`。绑定引用为 `id@version`。同引用内容不可覆盖；修改必须新版本。
- `name`: 最多 100 字符的显示名称。
- `description`: 最多 2000 字符，解释适用异常、可能影响和验证范围。
- `engine`: 支持 `responses-tools-v1`、`responses-tools-v2`、`responses-tools-v3`；未知引擎明确提示升级。新增能力必须通过新包显式选择，不能修改同引用旧包来悄悄升级。
- `options`: 必须显式填写 `lateName`、`splitCalls` 两个布尔值，无其他选项。
- `fixtures`: 1–16 个合成样例。每个包含 `name`、`events`（1–256 个事件对象）、`expectedCalls`（0–64 个按输出顺序排列的调用）。每个预期调用仅有 `call_id`、`name`、`arguments`，三者为字符串；参数是完整的 JSON 对象字符串。
- v3 的每个 fixture 还必须填写 `expectedTexts` 字符串数组，同时核对已完成 message 和最终快照的正文；无 message 时填 `[]`。

### responses-tools-v1 的处理方式

- `lateName`：允许在后续参数完成、item 完成或最终 output 中才出现工具名，依据可靠 ID / output_index 关联。
- `splitCalls`：在整条响应中**只有一个真实有名调用和一个匿名调用**时，允许合并声明和幽灵参数。多个候选不按“最近一次调用”猜，明确失败。这个约束意味着某些并行畸形流暂不支持；正常并行且 ID 清晰的工具调用可以处理。
- 为等齐晚到参数，所有 function_call 事件暂存到成功的 `response.completed`，再输出完整 added / arguments.delta / arguments.done / item.done，重写最终 output 和全局 sequence_number。文本及未知合法事件仍及时传递，output_index 随最终顺序保持一致。
- 不会把正常 `"{}"` 一概当成占位符，不伪造缺失参数或调用 ID。冲突、无效 JSON、失败/截断响应、索引缺失均不会包装成成功调用。错误摘要可在请求记录中查看；部分文本已发出时会中止响应，不切回原始畸形流，也不重试整次请求。
- 每请求独立状态；单 SSE 事件 / 单工具参数最多 1MB，工具暂存最多 4MB / 64 个调用，从第一个工具事件起最多等待 30 秒。收到上游原始数据仍会刷新代理原来的空闲时限，不能因缓存而误判上游空闲。
- 默认请求准备为恒等操作，仅要求 `stream: true`；不改提示词、角色、工具名、参数含义、UA、DNS 或 TLS。显式启用 `neutralizeCursorInstructions` 的适配包是例外：仅将 instructions 内确切短语 `You operate in Cursor.` 改为 `You operate in an editor.`，不修改其他字段；这会改变系统指令，仅应在有需要的模型上启用。

一种全新的跨事件算法不能靠修改上述 JSON 获得，需要补兼容模块实现及测试、升级引擎。仅支持 Chat Completions 的上游也需要另一项协议转换功能，本版不提供。

### responses-tools-v2：最终快照身份对齐

- 保留 v1 的两个 options 及工具事件缓存策略。只新增对 `response.completed.output` 重新生成 item ID 的受限处理，不容忍流内 added/done/参数事件任意换 ID。
- 对工具项，只有稳定且唯一的真实 `call_id` 能确定归属，才使用已有流内 item ID 重建最终快照。真实 call_id 不变；不按最终数组位置猜测，不吞掉名称/参数冲突，不允许 ID 占用其他工具或非工具身份。重复最终 item ID、call_id 均拒绝。
- 对已流式发出的 reasoning/message 等非工具项，没有 call_id 可依赖：只有与一个尚未匹配的已完成条目内容完全一致（忽略 id/status）才能对齐重新生成的 ID。未完成项、内容改变、重复消费同一个身份或多个同内容候选均拒绝，不凭位置配对。已出现非工具流内身份时，也不猜测额外的无匹配最终条目；这种混合格式暂不支持。
- v2 的 4MB 状态字节预算包含保留的 ID、索引、非工具完成项及最终快照，不是只统计工具参数。所有输出槽位必须无冲突，通过整帧身份、槽位及预算检查前不释放工具调用；不静默覆盖条目。
- 这是通用的协议异常处理，不以模型名触发。未绑定修复包的路由不变；v1 包和正在使用的旧版本请求快照不被自动升级。不能据此承诺其他模型所有工具问题都已解决。
- 实测 swe-2-max 的真实响应确有参数拆分及最终 ID 漂移；v2 已用保存的响应离线回放验证。修复后尚未做真实客户端完整工具执行/结果回传，不解决 Cursor/ZCode 请求侧拒绝、HTTP 502 或 Chat Completions 协议差异。

### responses-tools-v3：显式 think/response 正文边界

- 示例 `examples/pixel-swe-v3.adroute-adapter.json`（`pixel-swe-tools@1.2.0`）。新包不会自动安装、绑定或替换 v2。
- 针对已观察到的原始控制边界 `<|close|>think<|sep|><|open|>response<|sep|>`，仅在单正文部分、唯一完整边界且所有快照/增量一致时移除前缀；既有标准 reasoning 通道仍保持独立。普通中英文、代码及没有控制标记的文本保持不变，不声称能识别无标记的思考内容。
- 重复/不完整/被引用的边界、复杂多正文部分、注释或 logprobs 偏移需要重算的情况明确拒绝，不选最后一个标记、不按语言或自然语言句子猜测。原始 v2 身份校验先于正文修改，不能用删前缀掩盖快照身份冲突。
- 为避免边界晚到前泄漏前缀，**整个响应**暂存到成功完成才释放；最多 4MB、5 分钟（原代理空闲超时仍有效），有额外首字/工具延迟。失败或截断不释放缓存正文/工具；SSE 头已发送时客户端可能看到流中断，原因写入请求记录，不自动重试。
- 只修改响应正文中的这一种显式封装，不改提示词、角色、模型请求、工具 call_id 或参数。无法控制的上游可能产生其他格式，不能保证此包覆盖所有情况。

## 分清三种验证

1. **配置校验**：文件结构和引擎能力可接受。
2. **本地回放**：包内或诊断样例在本机归一化成功，包内样例还核对 expectedCalls 与最终 output。样例由提供者编写，不能证明覆盖全部情况。
3. **真实验证**：管理页可明确同意发送一次真实的“文本完成”或“工具流结构”探针，可能收费。工具探针只请求一次 `adroute_probe`，不执行任何工具；它仍不等于 Codex 真实工具执行和结果回传已验证。

仓库集成测试使用官方 Codex 与本地模拟上游完成工具往返（仅合成数据和无害 printf），包括修复后的拆分调用；不使用你的登录、上游凭据或真实上游。真实 Pixel 使用情况需要另行授权验证。

## 管理接口

均要求独立的管理员令牌及原有本机 Host/Origin 校验；不能使用代理令牌访问。管理页会拒绝对不声明 `capabilities.adapterDirectory` 的旧后台发送目录和 Prompt 操作。

- `GET /api/compatibility`：最新 `engine`、支持的 `engines` 列表、已安装版本和一次性诊断状态。
- `POST /api/compatibility/refresh`：显式扫描固定目录，校验并登记合格包，不绑定模型；返回目录问题与逐文件结果。
- `POST /api/compatibility/prompt`：可传 `modelId` 填入目标。仅 `includeDiagnosis: true` 与已审查 `diagnosisId`、条目身份和内容指纹核对成功才附诊断路径；不包含凭据。
- `POST /api/compatibility/remove`：传 `ref` 或直属 `file`，移除对应登记与文件；有绑定时拒绝，路径越界及目录删除拒绝。
- `GET /api/compatibility/template`：当前 v2 示例包；仓库仍保留 v1 示例供回归和旧版本参考。
- `POST /api/compatibility/verify`：包 JSON，本地验证，不安装。
- `POST /api/compatibility/packages`：保留的旧版导入接口，包 JSON 再次验证后登记；新页面使用固定目录刷新，不再提供上传安装主流程。
- `GET/DELETE /api/compatibility/packages/:ref`：导出或删除指定版本；被引用时禁止删除。
- `PUT /api/compatibility/selection/:modelId`：`{ "profile": "id@version" }` 或 `profile: "none"`；只修改这一项。旧 bindings 与 scope/inherit 结构不再接受。
- `POST /api/compatibility/diagnosis`：`modelId`、可选 `raw` 和 `consent`；只启用下一次匹配取样。
- `GET/DELETE /api/compatibility/diagnosis`：预览或停止并清除。
- `POST /api/compatibility/replay`：`{ "ref": "id@version", "events": [...] }`，在本机处理内容样本，不执行工具；最多 256KB / 256 个事件。

包和条目绑定保存在私有 `config.json`。路由和适配版本固定为请求到达时的快照；编辑只影响后续请求。新条目默认透传；不存在的包引用明确拒绝保存或路由，不自动关闭修复，也不换用其他模型。
