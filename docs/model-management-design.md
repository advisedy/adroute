# 自建模型组与模型管理设计

状态：已实现（配置 version 6 / 服务版本 0.1.0）。本文保留交互与行为约定；0.7.0 的初次实现与 0.7.1 的审查修复是历史记录，配置版本与服务版本号此后都已前进。

## 目标与范围

- AdRoute 是提供统一本地 Base URL 和代理密钥的模型代理，不以某个客户端为首页主线。
- 日常主线：添加模型 → 填上游连接 → 选择或手填真实模型 → 指定名称和组 → 保存并对外开放。
- 取消面向用户的“供应商 → Key → 模型”管理层级；组是用户分类，不承担地址、凭据继承。
- 本轮只整理现有 Responses 与模型发现能力，不新增 Chat Completions 或 Anthropic 转换。
- 订阅模型来源先移除，不保留隐藏的订阅管理产品分支；以后需要时重新设计。
- 保留现有 Codex/OpenCode 客户端配置接入、显式同步及已承诺的配置恢复行为。移除订阅来源不等于移除客户端集成。
- 不维护旧数据兼容、迁移或导入链路。开发测试仍使用独立临时目录，不自动安装、不修改运行中的服务或真实客户端文件。

## 术语和身份

一个模型条目包含：模型组、模型名称、上游 Base URL、上游 API Key、真实模型 ID、对外开放状态，以及现有逐模型兼容绑定。

- 每个模型恰好属于一个用户创建的组；同组可以混用不同地址和 Key。
- 一个模型的配置编辑不连带修改其他模型；不增加 Key 管理页、共享凭据池或自动轮换。
- 组名使用小写英文字母、数字、连字符，连字符不在首尾、不连续；名称全局唯一。
- 模型名称使用英文字母、数字、`.`、`_`、`-`；不接受中文、空白、斜杠或其他字符。非法输入直接解释错误并阻止保存，不转拼音、不自动清洗。
- 同组模型名称唯一；关闭的条目也占用名称。不同组可重名。整体确认时采用精确、区分大小写的名称比较，不自动改大小写。
- 真实模型 ID 保持上游原值，可以跨条目重复，不受上述公开名称字符规则限制。
- 新建时模型名称默认填入真实模型 ID；若不符合名称规则，提示用户另取名称。用户手动编辑名称后，不再被发现结果或真实 ID 输入覆盖。
- 编辑已保存模型的真实 ID 时，不自动修改其模型名称。
- 不再有第三个可编辑的模型路由别名。

对外模型 ID：`adroute/<组名>/<模型名称>`。客户端目录显示 `<组名> / <模型名称>`；即使某客户端只显示 ID，也不会使用上游真实 ID 作为选择标识。

示例：组 `work`、名称 `coding`、真实 ID `vendor/model`；客户端调用 `adroute/work/coding`，AdRoute 转发时使用 `vendor/model`。

## 页面结构

### 模型管理（首页）

1. 顶部紧凑的本地接入区：本地 Base URL、本地代理密钥、分别复制；密钥默认遮蔽，显式操作显示或复制。提示上游 Key 与本地代理密钥不同，仅支持当前已实现的协议。
2. 模型区：主要按钮“添加模型”；“全部模型”和用户组筛选，组的新增、改名、删除入口不嵌套到模型凭据管理中。
3. 每个模型直接显示组/名称、上游真实 ID 和地址概要、开放状态。Key 不显示在列表中；填了上下文窗口时在详情里显示一行。
4. 开放开关与三个并列的小按钮“编辑 / 测速 / 删除”直接出现在每条模型上；删除不藏到更多菜单。设为默认、兼容修复等通过次级操作或对应功能入口提供。
5. 测速结果显示在对应模型下方，不弹出复杂报告；测试中显示进度并可取消。
6. 已关闭模型仍可见、编辑与显式管理测速；测速不自动开放模型。空状态直接引导添加模型，不引导先添加供应商或 Key。

### 次级入口

- 客户端接入：统一接入说明、现有 Codex/OpenCode 配置接入、同步和恢复相关操作。
- 请求记录：保留请求结果查看，不保存对话正文。
- 兼容修复：保留逐模型修复绑定、包管理和高级诊断；目标改为组/模型，不再要求先选择供应商和 Key。
- 网页默认模型：次级可选设置，不作为首页大卡片或模型发布的必经步骤。

## 添加和编辑

在单个表单中填写上游 Base URL、上游 API Key、真实模型 ID、模型名称、所属组与初始开放状态。

- 获取模型使用表单当前填写的地址和 Key；结果只供显式选择，不自动保存全部结果。
- 上游没有模型发现接口时，仍可手工输入真实 ID。
- 表单内可创建组；从某组添加时默认选中该组，不创建隐藏的“未分组”分类。
- 新模型默认对外开放，但可以在保存前关闭；一个模型保存操作整体成功或失败。
- 保存不隐式推理。测速为独立显式操作，保留用量确认、取消和超时约束，具体行为见下节；工具流结构测试保留在高级兼容入口，不混入快速测速主流程。
- 重名、非法名称、缺失连接配置就地提示，失败保留草稿；后端同样验证并原子防止并发重名。
- 编辑表单的 Key 是明文，便于核对已保存的值；保存时只有值被改动才提交，因此陈旧草稿不会覆盖别处刚轮换的密钥。列表与卡片始终不显示密钥。不因刷新或错误丢失其他字段。
- 上下文窗口走独立的小对话框（模型行的“更多 → 修改详细参数”），只含一个数字字段，通过窄接口 `PUT /api/models/:id/params` 保存；不复用整份模型表单，避免陈旧草稿顺带改写其他字段。
- 只改地址、Key、真实模型 ID：对外 ID 不变，正常保存即可。不设替换向导、不要求额外确认、不强制重建条目或给名称加后缀。
- 修改组、组名或模型名称：提示旧对外 ID 将失效，确认后更新；不维护旧别名或回退路由。

## 快速测速

用户补充：测速与编辑、删除并排展示，目标是尽快检查能否正常调用，token/s 只需参考值，不建设复杂测速系统。

- 每次测速开始前给出简短的用量确认：会发送一次真实的短文本推理请求，可能消耗少量费用或额度。取消确认不发请求。
- 使用该模型保存的真实地址、Key、真实模型 ID 发起一次短文本 Responses 请求；不是只检查 models 接口或 TCP 连通。
- 固定简短提示词、限制输出并设置较短超时；不要求用户填写参数，不批量测速，不自动重试，不后台定时测试。
- 正常收到有效模型文本后显示“可用 · 约 XX token/s · 本次耗时”；只有 HTTP 200 或握手成功不算正常文本返回。
- 简单口径：优先取上游报告的 output_tokens，除以本次请求开始到有效完成的总秒数。包括等待时间，因此是本次请求的端到端平均输出速率，不宣称是纯生成速度；短样本、网络与推理耗时会影响结果。
- 验证终态及内部状态一致后立即结束，不等待连接关闭；失败不可被后续事件覆盖。超出本次输出预算的用量不作为可信速度，未知的提前结束原因不原样回显。
- 上游未返回可信输出 token 数时，显示“可用 · 速度不可统计（上游未返回用量）”；不将字符数或 SSE 事件数当成 token，也不为此引入多模型 tokenizer 或额外推理请求。
- 上游有效文本不足、返回错误、超时、取消分别清楚标注；达到短测输出上限的响应按其实际内容与终止原因解释，不把截断响应当成完整成功或工具兼容证明。
- 测速中同模型请求单飞；禁止重复提交，可取消。同一条目的编辑/删除在测试运行时暂不可用，避免结果挂到已经替换的目标上。
- 结果只作为当前页面中的最近一次检查，显示时间；修改上游连接或真实 ID 后清除旧结果，不增加排行榜、历史趋势、持久统计库或精准基准承诺。
- 退出登录、取消或离开目标后，晚到结果不恢复私有界面；取消与超时应中止后端上游请求，不只是让浏览器停止等待。
- 测速不会修改开放状态、默认选择或客户端配置；关闭条目仍可显式管理测速，不绕过对外路由关闭约束。

## 开放、默认、删除与目录刷新

- 已保存模型列表上的开放开关直接生效；同一条目操作进行中禁用重复操作，失败恢复已保存状态。
- 关闭当前默认模型继续保留确认，并在一次后端更新中清空默认；重新开放不恢复默认，不自动选其他模型。
- 关闭后的模型不进入外部目录，旧客户端缓存的 ID 也不能绕过关闭；已接收请求继续使用接收时的配置快照。
- 普通编辑不偷偷开放已关闭条目；设置默认也不改变其他模型的开放状态。
- 删除模型明确确认；有模型的组不可删除，需先显式移动或删除条目。移动前检查目标组重名，不自动改名。
- 已删除或已关闭条目不自动回退到其他模型或 Key。
- 改名、换组、增删或开放状态变化影响目录；提示外部客户端刷新目录，必要时重新选择。不声称所有客户端可以自动刷新。
- 仅改上游配置且对外 ID 不变，通常无需重新获取目录，后续请求按新配置处理。
- 模型配置保存与客户端目录文件发布分开报告：若目录发布失败，明确提示“配置已保存，目录待发布”，提供只重试目录发布的按钮，不要求重复保存模型。
- 对外 ID 按当前组/名称寻址：用户主动删除后重建同名条目，或主动修改其上游目标，属于用户对该名称的重新配置。不增加历史名称封禁、路由版本或迁移映射。

## 保留的安全约束

管理认证、代理认证、凭据保护、请求快照、原子保存、配置恢复保护和异步退出登录隔离不因界面简化而删除。涉及真实客户端文件的写入继续遵守既有明确操作与恢复约束；本次讨论和草图不会执行这些操作。
